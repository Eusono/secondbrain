# Permanent Memory Index (`memory/MEMORY.md`)

This file is the single index for permanent, cross-cutting memories, entity profiles, preferences, and durable facts that do not belong exclusively to a single topic folder.

---

## Memory Guidelines

1. **Keep it Lean (One Line Per Entry):** Summary entries here point to slug-named detail files (`memory/<slug>.md`).
2. **Three Memory Archetypes:**
   - **People, Teams & Contacts (`memory/<person_or_team>.md`):** Roles, ownership boundaries, and escalation contacts.
   - **Architecture & Topology (`memory/<arch_or_site>.md`):** Cross-cutting system/network design and site facts that outlive individual tickets.
   - **Living System Cards & Skill Routers (`memory/system_<name>.md`):** Concise (`30–60` line), secret-free operational cards (or pointers to `skills/<name>/SKILL.md`) capturing how we authenticate, query APIs/databases, and avoid distilled gotchas from `skills/lessons.md`.
3. **Point-in-Time Observations:** Memory files record dated facts observed at a specific time. Before asserting a memory as fact, verify against live state.
4. **No Duplicates:** Search this index before writing a new memory file; consolidate into the existing card rather than minting duplicates.
